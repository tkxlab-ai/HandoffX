### 2026-05-06 07:24 — v1.2.9 发版：Codex 第三轮 adversarial review，修 1 架构 high——preflight 闸门被 skip 逻辑掏空

**触发**: v1.2.8 commit (`74f1b61`) 后跑第三轮 codex adversarial review（base=`b973251`）。前两轮的 4 条 high（OpenCode 路径 / .bak 泄漏 / Codex 项目路径 / docs/superpowers 泄漏）确认全闭环；但发现新 1 条架构层 high：v1.2.7 引入的 `test_release_artifact_content.sh` 的 "Release/latest 版本号 ≠ dev VERSION 时 skip" 机制实际让该测试**永远在 release preflight 阶段被跳过**——本会话三次发版（v1.2.6/v1.2.7/v1.2.8）这个"闸门"从未真正检过 about-to-be-released 的 tarball。事后兜底但马后炮，不是真闸门。

**改动**:
- `tests/test_project_tree_forbidden.sh` —— 新增；preflight 阶段扫**项目根**是否含 `Handoff_OldBackup_*` / `Handoff_planning_*` / `docs/superpowers/`。无 skip 逻辑——项目树是当前可观测状态，任何时候都可断言；TDD 双向验证（clean 时 3/0 绿；临时建 symlink 时 2/1 红）
- `HANDOFF.md` Gotcha #12 —— 闸门三准则：(a) 检查当前可观测事实；(b) 失败真阻塞下游；(c) 不能有 skip-when-X 让闸门退化为 noop。skip 逻辑是 anti-pattern
- `HANDOFF.md` / `README.md` 当前版本字段 → v1.2.9
- `CHANGELOG.md` + `Release/CHANGELOG.md` —— v1.2.9 完整条目
- 走过的弯路:
  - 第一版测试用 `nullglob + matches=( "$ROOT_DIR"/$label )` 想统一处理 glob 和字面路径，结果发现 bash 对**不含 glob 字符的字面路径**直接返回字符串不查存在性——`docs/superpowers/` 这种字面 label 即使路径不存在也展开成数组里的 1 个字符串元素。修法：在每个展开后加 `[ -e ]` 二次过滤
  - 想过把 artifact-content 测试改成 always-run-without-skip，但那会让 release-in-flight 时 preflight 被旧 artifact 卡住——本质和 codex Round 3 finding 同根。单独建 project-tree 测试更干净，不和已有 artifact-content 测试纠缠

**验证**:
- `bash tests/test_project_tree_forbidden.sh` clean → 3 passed；建临时 symlink → 1 failed（验证抓得住）
- `bash tests/run_all.sh` → **21 套件 / 359 passed / 0 failed**（v1.2.8 是 20/356；本次 +1 套件 / +3 断言 = project-tree-forbidden）
- `gitx-release --version v1.2.9` → 🎉 Deep Audit PASS（197/0/1 SKIP/0 WARN）
- `Release/handoff-v1.2.9/` 完整产物（.skill 52K / source.tar.gz / full.tar.gz / SBOM / checksums）
- `Release/latest` → `handoff-v1.2.9`（原子更新）

**关联**: 新 Gotcha #12（preflight 闸门设计准则）；codex Round 3 单条 high 已闭
