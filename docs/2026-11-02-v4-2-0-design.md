## 1. 范围（七项）

### ① `scripts/hx.sh` — 写入流程的唯一 CLI 入口（报告 2 #11/#21/#17 母题）

`#!/usr/bin/env bash`、`set -euo pipefail`，自己 source `lib/handoff-schema.sh` + `lib/handoff-v2.sh`（lib 在非 bash 下拒绝加载的保护保留；hx.sh 因 shebang 永远在 bash 里）。子命令全部非交互、stdout 纯数据、诊断走 stderr：

| 子命令 | 行为 | exit |
|---|---|---|
| `now` | `date` 一次采集，打印三行：`human=2026-11-02 18:12` / `fm=2026-11-02T18:12` / `fn=2026-11-02T1812`（消灭 P10「文件名形态写进 frontmatter」） | 0 |
| `next-number logs\|decisions [--root DIR]` | 包 `acquire_next_number`。**lib 本身补强**（含孪生）：flock 分支的 `touch` / 打开锁文件 / `flock`、mkdir 分支的 `hx_take_lock`，每一步显式检查，失败 → stderr ❌、return 1、**不打印编号**（`||` 上下文里函数内 `set -e` 失效，不能靠它）。取号时持锁、返回即释放，编号不保留（HX-07 不做）。打印 `NNNN` + 换行 | 0 / 2 用法 / lib rc 原样透传（失败时 stdout 为空） |
| `slug "<标题>"` | 包 `slugify` | 0 / 2 |
| `regen [--root DIR]` | **先自检**：`--root` 是目录、`<root>/$HX_MAIN_FILE` 是可读普通文件，否则 exit 2（lib 的两个 helper 对缺文件/缺目录是成功 no-op，不能只透传）；再 `regenerate_pointers` + `regenerate_decision_index`，失败即其 rc | 0 / 2 前置不满足 / lib rc |
| `dup-check --files a,b,c [--root DIR]` | 规范「重复检测」的可计算谓词（§2） | 0 无重复 / 3 疑似重复 / 2 用法或无法判定 |
| `block get <name> [--file F]` / `block set <name> --from <path> [--file F]` | 锚点块读写（§3） | 0 / 2 文件或 `--from` 读不到（含存在但不可读）、或**零锚点** / 4 锚点重复、不成对或顺序非法；任何失败都不改目标文件 |

`--root` 默认 `.`；`--file` 默认 `<root>/HANDOFFX.md`。无四件套字面量（schema lib 常量；`test_handoff_schema.sh` 九 token 守卫照旧）。`skills/handoffx/scripts/hx.sh` 孪生 byte-identical（`test_scripts_sync.sh` 自动覆盖）。

指令层改写：SKILL.md 写入步骤 2/3/4/5/6/8、`references/handoffx-write.md`、四个 shim 对应行、**`assets/HANDOFFX.template.md` 末尾的 `<!-- 🚨 AI 注意 … -->` 注释**（现写的是直接调 `acquire_next_number` / `regenerate_pointers`，改为 `hx.sh` 三步，文件命名示例放进反引号——xref 对代码段豁免，裸 `<NNNN>` 会被当残留占位符）——`date` 改 `hx.sh now`、重复检测改 `hx.sh dup-check`、取号/slug 改 `hx.sh`、Current State 改 `hx.sh block set`、第 8 步改 `hx.sh regen`；旧的 `bash -c '. …'` 在 write.md 保留一处「等价手工命令」，其余删除。recall / tidy / init 不变。

### ② `dup-check` 谓词（替代 write.md「重复检测」第 1–5 条手工步骤）

1. `ls <logs>/[0-9]*.md | sort | tail -1` 取顶部条目；目录不存在或为空 → stdout `first-entry`，exit 0；目录存在但**读不了**（枚举失败）→ stderr `❌ 无法判定`，exit 2（不是 `ok`，Gotcha #24）。
2. frontmatter `date:`（`YYYY-MM-DDTHH:MM`）转 epoch（本地时区；macOS `date -j -f` / GNU `date -d` 择一，输出须纯数字，否则 exit 2「无法判定」）。`now - that < 600` 才继续，否则 stdout `ok`，exit 0。
3. 路径集合（两边同一规整）：反引号包裹的 token，去 `:行号` 尾巴与尾 `/`，**相对项目根真实存在**（文件或目录）的才算——仓库名、commit SHA、分支名自然滤掉。上一条取自其正文 `**改动**` **或** `**Changes**` 段（write.md 的英文别名契约；段落到下一个 `**字段**` 行为止）；本次取自 `--files`。
4. 两集合都空 → `ok` exit 0；非空且**完全相等** → stderr 打印规范的 ⚠️ 三行（分钟数、旧标题、集合），exit 3；否则 `ok` exit 0。
5. AI 见 exit 3 才问「替换 / 追加 / 取消」；0 直接写。write.md 的手工步骤改为引用本谓词。

### ③ Current State 锚点块（报告 2 #13）

锚点语法 `<!-- hx:<name> -->` … `<!-- /hx:<name> -->`，`name` 为 `[a-z0-9-]+`。三个约定块；块外内容（引用提示行、fleet 表、其它 `###` 小节）写入流程**不碰**：

| 块 | 内容 | 写入语义 |
|---|---|---|
| `hx:recent` | 状态行（`**最近改动区域**` / `**验证状态**`；项目可多一行 `**日期**`） | 每次 `block set` 整块覆盖 |
| `hx:done` | `### 最近完成` 累积列表（可选，本仓有） | AI 在列表顶部加一行（块内增量） |
| `hx:pending` | `### 待办…` 到节尾 | AI 块内增量编辑 |

模板 Current State 改为：引用提示行 → 空行 → `hx:recent`（现有两行状态字段原样）→ 空行 → `hx:pending`（现有 `### 待办` 与示例项）。不加新字段。
`block set`：awk 把两锚点之间整段换成 `--from` 文件内容（锚点行保留；mktemp + mv 原子写；目标是符号链接或非普通文件 → exit 2，沿用 X7）；退出码见 ① 表。
写入规范：有 `hx:recent` → `hx.sh block set recent --from <tmp>`；`done`/`pending` 由 AI 在块内编辑；无 `hx:recent`（老项目或只有其它块）→ **先跑 `tidy-handoff.sh` 补锚点（tidy 总会生成 `hx:recent`，没有状态行则为空块，且不动已有块），再 `block set`；永不整节覆盖**（v4 原稿的「沿用整节覆盖」已被最终审查裁定取代——整节覆盖会抹掉已存在的 `hx:done`/`hx:pending`）。
tidy 补锚点（结构性、不动内容、幂等；节内已有任一 `hx:` 锚点 → 不动）：节首的空行与 `>` 引用行留在块外；之后到第一个 `### ` 标题前 → `hx:recent`；`### 最近完成` 小节 → `hx:done`；`### 待办` 开头的小节 → `hx:pending`；其它 `###` 小节不包。本仓 dogfood：三块各得其所。validate 对无锚点只出一行 ℹ️（不算失败）。

### ④ 凭证表头启发式（报告 2 #12）— 已实现（Task 2，含两轮修复）

`scan_table_secrets <file>` → 0 / 1 / 2（无法扫描）；表头 = 表块第 2 行的分隔行之上一行，**或**第 2 行之后「每格都是 `:?---+:?`」的行之上一行（相邻表）——敏感列取**并集**，一个表块内只增不减，只在非表行清零；ASCII 关键词词边界（裸 `pass` 两侧、其余右侧、不允许复数）、`passphrase` 在列、CJK 子串；占位规则按 v3；字节类经 `-v` 传入（mawk 容器实跑 149/0）。不进公开脱敏（parity 只看正则数组）。

### ⑤ `handoffx-upgrade.sh --scan-home`（报告 2 #26、报告 4 #10）

第四种互斥模式，不接 `--root`。只报不改，固定根（存在的才扫；`$HOME` 取自系统变量）：`~/.claude/CLAUDE.md`、`~/.claude/rules/`、`~/.claude/commands/`、`~/.claude/skills/`、`~/.codex/`（AGENTS.md + `skills/`）、`~/.agents/skills/`、`~/.config/opencode/`（`command/` `commands/` `skill/` `skills/` `AGENTS.md`）。
**符号链接策略**：根路径带尾 `/`（跟随链接根，`scan-credentials.sh` 同例）+ `find -L`（跟随子目录链接；`-maxdepth` 限深；循环与悬空链接由 find 的 stderr 报出 → 「扫描不完整」exit 2，并列出路径）。
两类检查：
1. **文本残留**：与 `leftover_scan` 同一正则（抽成 `legacy_re()`）、同一 prune/skip 表、同一批次状态处理（`sh -c 'grep …; [ $? -le 1 ]'`、各阶段 rc、「枚举的文本文件数 == 实际扫描数」），按根分组输出 + 每文件首条（复用截断 awk）。
2. **旧名 skill**：各 skills 根下 `find -L -maxdepth 3 -name SKILL.md`（含隐藏目录，Gotcha #28），父目录名 **或** frontmatter `name:`（只看文件起始 `---`…`---` 块；去成对引号）属于旧名集合 → `⚠️ 旧名 skill 仍会被加载：<路径>（name: …）`。集合由 `_HXO` 拼接。
判决与 exit：完整且无命中 → ✅ exit 0；有命中 → 清单 exit 0；0 个根存在 → `ℹ️ 无可扫描根（0 个根存在）` exit 0 且无 ✅；任一阶段失败、根读不了、枚举≠扫描 → `⚠️ 扫描不完整` exit 2。`migration-order.md` 与 MIGRATION_GUIDE §5.6 第 2 步加一句。
