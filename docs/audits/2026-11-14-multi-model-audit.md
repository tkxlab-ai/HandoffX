GitNexus 本轮仍返回无可用索引，项目也无可用 graphify 图，因此采用直接源码与调用链核对；未为了审计安装或重建索引。

## 2. 总体裁决

与上一轮 14 组问题合并后，整理为 **22 个工程工作项**，而不是将模型输出直接相加当作 32 个已证实漏洞。

- **第一优先：5 个 P1 修复项**。显式文件漏扫、memory 失败丢旧副本、归档同名覆盖、失败后仍维护、tidy 修重号造成元数据不一致。
- **随后修复：P2 契约一致性**。frontmatter、引用、原子写与权限、轮换状态、章节识别、非法参数。
- **体验升级：**完整初始化/修复、doctor、分层 recall、低重复检查、v2 评测、多 Agent 事务写入。
- **暂缓：**默认跳过旧内容安全扫描、自动删除历史知识、直接改全套文件名、仅靠 mtime 的安全缓存、只加占位但无恢复协议。

模型一致赞同只代表候选问题值得优先验证，不等于正确；模型未发现也不推翻主审已复现的问题。前三项旧故障在新报告里没有被完整重述，仍保留为 P1。

## 5. 合并工作项与验收要求

### R01 · P1 · 显式检查目标漏扫

- **裁决：**必须修复。来源：F04; N02。
- **位置：**`scripts/handoff-postflight.sh:121; scripts/scan-credentials.sh:256-311`
- **依据：**显式v1文件直接扫描exit1，postflight却exit0。
- **方案：**扫描集合必须包含显式选中的主文件，再合并布局文件；统计实际覆盖，区分无输入与未命中。
- **验收：**旧布局和自定义主文件的模拟凭证均被拦截；不得以0文件扫描代表安全。

### R02 · P1 · memory先删后复制及成功误报

- **依据：**复制失败会丢旧副本；on仍报告同步成功。
- **方案：**目标同目录暂存，显式检查复制与扫描，成功后替换；区分IO失败与凭证命中。
- **验收：**on/sync失败均非零、旧副本不变、不增加成功计数。

### R04 · P1 · 检查失败仍执行归档

## 6. 不直接采纳或调整的模型建议

| 候选建议/判断 | 主审决定 | 理由 |
|---|---|---|
| 提前归档或跳过归档扫描即可消除开销 | 不采纳作为主要优化 | 扫描器仍扫描archive；跳过会削弱安全覆盖，搬文件也不节省总存储 |
| 全部rotation exit 1都改为总exit 0 | 不直接采纳 | 临近到期、已过期、解析失败、无法读取应分别定义，允许strict策略但不能混淆 |
| 日期带尾注必然漏报 | 撤回普遍断言 | 本机带尾注样例仍触发到期；只确认不可解析值无提示跳过 |
| CRLF必然被tidy明确拒绝 | 修正 | 普通CRLF条目实测tidy仍说干净；特定紧凑日期规整分支才显式拒绝 |
| 新增凭证前缀均零误报 | 不采纳保证 | 示例、占位符、公开JWT样例等需要负例和规则置信分层 |
| 将14个规则合并便可快14倍 | 不采纳数值承诺 | 表格扫描、占位过滤、错误语义与其他检查仍耗时；须实测且保持结果集合一致 |
| 直接支持所有中文文件名解决可读性 | 暂缓 | 先用标题索引/列表提升体验，不破坏现有跨平台路径契约 |
| 用临时占位文件解决并发即可 | 方案不完整 | 崩溃后占位、正式日志可见性、重试和锁范围都需协议；不要把半成品当日志 |
| 以mtime不变为由跳过安全扫描 | 不采纳单一条件 | 同秒修改、恢复时间戳和规则版本变更都要考虑；全量模式必须保留 |
| 再归档/覆盖旧发布内容让DeepAudit变绿 | 不采纳 | 先区分当前源码漂移与发布快照损坏，不改历史以消红 |
| tidy缺少shasum回退 | 保留验证项 | 源码确有依赖；本轮未在无shasum的Linux环境测后果，纳入doctor/平台测试，不升级为已复现数据损坏 |
