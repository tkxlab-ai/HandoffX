# 2026-11-15 三端真实 CLI 与 Linux 验收

## 范围与方法

本轮只执行验收，不修实现、不提交、不发版。测试项目均为临时目录，未在真实项目执行 handoff 写入或归档。复用本机已配置的模型路由，不添加项目运行时依赖。

- 写入：空项目 + eval 1 的三处 TypeScript 改动与 A/B 技术权衡。检查四件套、Dev Log、Decision、精确引用、来源忠实性、机械步骤与验证。
- 召回：v2 七条日志 fixture，实际命令请求最近三条；Codex 另测默认六条。对比路径、内容 SHA256、mtime、权限及链接信息，并检查工具轨迹。
- 字数：统计完整模型流中所有 assistant 可见文本，含开始/进度说明、标点、路径和换行，按 Unicode code point 计数；不重复计算流末尾的 result 回放，不计思考、工具输出或宿主工具卡片。由此不能推导交互式 UI 已隐藏工具调用或代码。
- 这是选定真实行为用例，不是九个 eval 场景的完整通过证明，也不是完整多模型补丁复审。

## Linux 回归

执行仓库已有 `bash tests/linux-container.sh`，默认非 root 模式。启动原已停止的 OrbStack 后完成，脚本退出0：**40套、3627个运行期断言通过、0失败、实际0跳过**。

环境：Ubuntu 22.04 / Linux aarch64 / Bash 5.1.16 / mawk 1.3.4，测试用户 UID 501，容器内 python/python2/python3 均不可用，包信息确认 Python 3 未安装。测试使用脚本生成的独立副本；代理前后核对真实仓库2607项，无变化。

包装脚本末行显示 `12 ➖`，但内部 runner 最终明确 `skipped: 0`：包装脚本按字符 grep 计数，把成功断言描述中的符号也算入。应修统计方法，不能误报12个跳过。完整包装脚本stdout/stderr已保存；额外抓取的内部日志尾部不完整，不冒充完整内部日志。临时容器已自动删除；OrbStack保持运行，未停止已有容器。

macOS本轮另跑简短输出脚本契约测试：27个断言通过。它只证明脚本/文档契约，不能覆盖真实模型的进度说明和内容忠实性；以上行为失败正是静态断言未覆盖的部分。

## 优先修复建议

1. **P1：完整可见回复的200字门禁。** 三端验收统计必须覆盖全部消息，不能只数最终答复。需要处理技能读取前的进度说明，评估 CLI 路由与宿主行为；不能只在规范里重复增加“简短”要求，也不能静默截掉错误信息。
2. **P1：交接事实归因。** 未知测试覆盖范围保留为“待确认/建议核查”，不能转写为已确认缺口。对最终状态与待办也做忠实性检查，而非只检查 Dev Log。
3. **P2：可靠定位技能。** shim 应绑定本端可解析的技能根；查找失败时有界报错，不全盘扫描、不隐式跨用其他端安装。
4. **P1/P2：参数与慢路径。** 为三端统一验证纯数字、带自然语言说明与默认条数；OpenCode首次写入需减少重复读规范/初始化说明，保留超时后的明确未完成状态。
5. **P2：机器可读测试统计。** Linux包装层读取 runner 的真实跳过计数或结构化报告，避免按图标全文计数。

在行为问题修复并复测前，不将当前版本标为三端验收全绿。
