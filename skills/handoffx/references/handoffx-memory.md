# `/handoffx-memory` — 实验性项目记忆同步规范

启动时仅提示「🚀启动handoffX项目交接流程.」一次；宿主已显示则不重复。执行中的异常、警告、阻断和必要确认应及时正常提醒，不受常规字数或单次回复限制，不必等到结束或用户要求详情；需要确认时暂停相应操作。不得泄露凭证，正常进度不反复播报。

> 🧪 **Experimental**：API 可能变。默认关闭，用户显式 `on` 才启用。

## 背景：为什么要这个命令

Claude Code 的 "auto-memory"（feedback / project / reference / user 四类记忆）默认存在 **机器本地**：

```
~/.claude/projects/<encoded-path>/memory/
```

其中 `<encoded-path>` 由项目绝对路径派生（`/` `_` `.` → `-`）。当前同步脚本仍从 `$HOME/.claude/projects/<encoded-path>/memory/` 取源；安装器的 `CLAUDE_CONFIG_DIR` 覆盖**不会**改变这个源路径（`HOME_OVERRIDE` 仅为测试 hook）。这意味着：

- ✅ 同一台电脑上 Claude 能持续记住本项目的经验
- ❌ 换电脑 / 换同事 / 换 AI 工具时，记忆**不跟着项目走**——项目文件夹里没有任何痕迹

`/handoffx-memory` 是一个 opt-in 的桥：**把 CC 的 auto-memory 固化到项目 `./memory/` 目录**，这样项目文件夹打包带走，记忆文件就跟着走；这不代表其它机器或 AI 工具会自动加载这些文件。

这与 HANDOFFX.md 的核心原则（Non-Goal：不做对话历史导出/重放）**并不冲突**——记忆是压缩过的经验条目，不是对话原文，且本功能是 opt-in 例外。

## 子命令

| 命令 | 行为 |
|------|------|
| `/handoffx-memory` | 显示状态（enabled/disabled + 已同步文件数 + 源路径） |
| `/handoffx-memory on` | 启用：创建 `./memory/.sync-enabled` 标志 + 立即跑一次同步 |
| `/handoffx-memory off` | 关闭：删除标志文件；**已同步的 .md 文件保留**（用户想清掉自己 `rm -rf ./memory/`） |
| `/handoffx-memory sync` | 不看标志，强制同步一次（手动触发，或供 `/handoffx` 自动调用） |

## 执行流程

1. **定位脚本**：使用当前生效技能的 `<skill-path>/scripts/sync-memory.sh`；Claude 默认安装在 `~/.claude/skills/handoffx/`，全局安装可由 `CLAUDE_CONFIG_DIR` 改变，项目级安装仍在 `.claude/skills/handoffx/`。安装位置与记忆源位置不是同一个配置项。
2. **首次 `on` 前的确认**（只在首次，即标志文件不存在时）：
   ```
   ⚠️ 这是实验性功能。启用后：
     • 会在项目根创建 ./memory/ 目录
     • 先暂存 ~/.claude/projects/<encoded>/memory/*.md，扫描通过后再逐文件发布到 ./memory/
     • 之后每次 /handoffx 会尝试重新同步（同名覆盖，不删除本地额外文件）
     • 换电脑时可携带 ./memory/ 文件，按需读取；不会自动装入其它工具的记忆
   继续？（y/N）
   ```
   如果用户在命令里已经明确写了 `on`，视为已确认，直接执行。
3. **调用脚本**：在用户明确的项目物理根执行，禁止以父目录或仅凭当前cwd猜目标；on/off/sync均逐次校验根。`bash <skill-path>/scripts/sync-memory.sh --expect-root "<已确认项目绝对路径>" <subcommand>`
4. **回显输出**：原样转发脚本 stdout/stderr，别包装得看不清证据

## 与 `/handoffx` 写入流程的集成

如果 `./memory/.sync-enabled` 存在，`/handoffx` 在后置检查之后、最终回显之前额外调用：

```bash
bash <skill-path>/scripts/sync-memory.sh --expect-root "<已确认项目绝对路径>" sync
```

标志不存在则跳过。无异常的 `/handoffx` 除统一启动提示外**仅一次结果回复，所有常规用户可见说明合计 ≤200 字**（含标点、路径），不重复播报正常进度，不贴代码、命令或长检查清单；**启用且同步有异常时**及时正常提醒，不为同步成功额外发送提示。有必要提醒或用户明确说“详细/展开”时展示相关路径和必要错误详情，不能回显凭证原文。短回复不减少实际检查。

直接调用 `/handoffx-memory` 仍按上面的执行流程回显其状态/同步结果，不应把它与 `/handoffx` 的默认短回复混为一谈。

## 与 `/handoffx-recall` 的关系

`/handoffx-recall` 不主动加载 `./memory/*.md` 正文；仅在启用同步且用户明确说“读记忆”或“load memory”时按需读取。默认报告不固定追加记忆文件计数或实验功能提醒。

`/handoffx-recall` 的启动提示仍简短，但正文默认完整展示交接背景、上次完成、全部待办、下一步、风险及交接时间，不受120/200字限制，也不调用短确认门禁。记忆内容仅在与当前交接相关时补读；读取失败说明缺口，不声称已读。记忆文件随项目携带，不等于已被 recall 加载。

## 规则

- **只操作 `./memory/`** —— 不碰 HANDOFFX.md，不碰 git，不碰 `~/.claude/`（只读 CC 源）
- **覆盖式同步，不做镜像** —— 先暂存并验证，成功后逐文件替换同名副本；项目本地多出的 `.md` 不删除，但会纳入发布前扫描。
- **源不存在不是错误** —— CC 没记忆就是没记忆，脚本 exit 0，打印提示即可
- **不把 `./memory/` 加 .gitignore** —— 是否入版本由项目自己决定；但**首次 `on` 且检测到 `.git/`** 时会提示用户考虑手动加入（见下）
- **每次 `on` 都尝试一次 sync** —— 先创建 `.sync-enabled`，再同步；同步失败不会自动删除该标志，也不会打印启用成功。可修复后重试或显式 `off`。
- **实验性标记要保留** —— 本命令描述及相关提示保留 🧪 / "experimental"；不要因此在普通 handoff/recall 回复里重复实验功能提醒。
- **拒绝 symlink** —— CC 源里的 symlink 一律跳过（防攻击者植入 `/etc/passwd` 等链接被当作记忆同步进项目）
- **发布前验证，逐文件发布** —— 所有待发布文件及未被替换的本地文件扫描通过后才开始发布。预发布失败保旧副本；发布阶段不是整批事务，中途失败不回滚此前已发布文件。

## 敏感信息保护（自动化）

### 暂存 → 凭证扫描 → 逐文件发布

每次 `sync` / `on` 的同步阶段按下列顺序执行：

1. 源目录不存在：提示并 exit 0，不更新已有副本。源目录不可读/不可遍历：exit 2。
2. 在目标文件系统内创建 `./memory/.sync-memory.*` 暂存目录，把源中的普通、非隐藏 `.md` 文件复制进去并设置用户可写；不跟随源文件 symlink。复制、权限设置、暂存创建或目标目录冲突失败，exit 2，旧副本不变。
3. 用 `scan-credentials.sh` 扫描**暂存中的新文件 + 不会被替换的本地 `.md` 文件**。同名旧版本即将被替换，只扫它的新版本；隐藏文件不在此次扫描范围。扫描器识别 **14 类凭证模式**及敏感表头列启发式，覆盖边界以其 `--help` 为准，未命中不代表不存在任何敏感内容。
4. 只有整批扫描通过才逐文件 `mv` 发布。每个文件独立替换，**不是整批事务**：中途发布失败返回 exit 2，并报告此前已发布的数量；失败文件的旧副本保留，此前已发布的文件不回滚。未发布的暂存文件由退出清理删除，修复原因后可重跑。

凭证命中时示例：

```
🔴 凭证扫描：待同步记忆中检测到疑似凭证！
   • feedback_xxx.md

   建议：编辑上述文件把明文密钥换成 $ENV_VAR 或 vault://；
   然后重跑 /handoffx-memory sync。或 /handoffx-memory off 关闭同步。
```

此时**尚未发布任何文件**，旧副本保持不变。若命中的是待同步文件，应修改 Claude Code 记忆源再重试；若命中的是不会被替换的本地文件，则修改对应 `./memory/` 文件。不要只改临时副本，也不要把失败解释为同步成功。

同步退出码：

| 退出码 | 含义与保留范围 |
|--------|----------------|
| `0` | 同步完成，或源不存在/没有可同步文件；以实际输出区分，不能凭 exit 0 宣称复制了文件。 |
| `1` | 发布前凭证命中，未发布、旧副本保留；未知子命令/部分用法错误也返回 1。 |
| `2` | 同步 I/O、发布失败，或扫描器缺失/文件无法扫描。预发布阶段失败不动旧副本；发布阶段失败可能已完成部分文件，不能声称整批回滚。 |

无法扫描不按 clean 处理；若同时有凭证命中和扫描失败，返回 2。首次 `on` 的标志写入发生在同步之前，失败后标志仍可能存在，需另行 `off` 才关闭后续自动同步。

### `.gitignore` 提示（仅首次 on）

第一次 `on`（标志文件本来不存在）且项目根有 `.git/`，且 `.gitignore` 没包含 `memory/`：

```
💡 检测到 .git/ 仓库。本项目的 ./memory/ 即将随 commit 进入版本管理。
   如果记忆里可能含客户名 / 内部 URL / token 等敏感内容，建议加入 .gitignore：

     echo 'memory/' >> .gitignore

   （这只是提醒，不会自动添加——记忆是否入版本由你决定）
```

非 git 仓库、已忽略、或第二次 on → 静默不打扰。
