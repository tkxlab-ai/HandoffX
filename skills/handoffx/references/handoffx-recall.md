# `/handoffx-recall` — 只读有界召回

启动时仅提示「🚀启动handoffX项目交接流程.」一次；宿主已显示则不重复。异常、警告与必要确认及时提醒，不复述凭证；不输出读取、检查、整理等普通进度，只显示启动原句和最终报告。只读不写，不git、不SSH、不运行测试、不自动执行待办。

读取规范、执行context/recall及整理报告都直接调用工具，不另发“先读取规范”“规范已读取”“开始检查”等普通进度；这些句子也不并入最终正文。异常与真实警告仍及时报告。

默认保留项目方向、当前接手状态 + 最近6条有界摘要，不是完整历史回放。准确接手、不偏离方向是目标，不以压缩比例验收。**正文不受120/200字限制**，但不能靠缩短回答掩盖工具输入膨胀，也不能删减当前未完成事项。

## 技能根与参数

使用入口给出的技能根；Codex alias 的根为该 alias 文件目录的 `../handoffx`，主技能则为其 SKILL.md 所在目录。根不存在即停止，不全盘搜索、不切换其他CLI安装、不重读入口。

先在明确的项目目录执行 `bash <技能根>/scripts/handoff-runtime.sh context --root "<项目绝对路径>" --skill-root "<当前技能根绝对路径>"`。错根、移动安装或local/global技能冲突就停止，不自动向上查找、不换工具/技能重试。绑定只证明这些路径一致，不证明代码副本身份；`source_unbound`明确标未绑定源码工具，不能冒称已验证项目身份。recall自身也校验绑定。

| 输入 | 读取条数 |
|---|---|
| `/handoffx-recall` | **6**（默认） |
| `/handoffx-recall 3` | 3 |
| `/handoffx-recall 3。只读汇报` | 3 |

在项目根执行 `bash <技能根>/scripts/handoff-runtime.sh recall "<原始参数>"`。去掉调用名后将剩余原始参数作为一个字符串传入，不自行取数；无参数传空串，不传未展开的 `$ARGUMENTS`。默认6；`3` 或 `3。只读汇报` 均取3；0、负数、溢出拒绝，没有开头数字才用默认6，每次独立。N只限制近期日志数量，不限制待办数量；增加N仍受总预算限制。

## 一次采集与预算

只使用运行时返回的有界资料，不重新列目录或自行拼装全文。预算均为 **UTF-8字节**，不是模型token；各单项上限不是可同时填满的配额，总量仍须满足24576字节。方向区/状态/TODO超限不自动删减；日志摘要按从新到旧占用剩余预算，放不下的较旧日志显式降级为元数据：

| 范围 | 上限 | 超限处理 |
|---|---:|---|
| stdout总量（含元数据与换行） | 24576 | 必需资料放不下时非零退出，stdout为空 |
| 当前状态（recent、完整pending及锚点外补充上下文） | 12288 | 非零退出，stdout为空，不截断任务 |
| Project Overview 内唯一 `hx:continuity` 块 / 无块的旧Overview | 4096 | 原文保留；超限非零退出，stdout为空，绝不整段延后 |
| 每条日志摘要 / 无摘要短日志全文 | 2048 | 旧长日志降级元数据；摘要超限则非零、stdout为空；总预算不足时标 `summary_deferred_budget`，仅给标题/时间/路径 |

- Project Overview 内唯一 `<!-- hx:continuity -->` … `<!-- /hx:continuity -->` 是权威方向区：总目标、受益者与问题、成功标准、范围与非目标、关键技术/安全/兼容性约束与授权门控、仍有效决策及原因/出处。不在别处重复同一可变事实。显式块原文返回（≤4096 UTF-8字节），状态为 `continuity_status=explicit_unverified`；块外长背景按需加载，但当前有效关键信息不得仅留在延后资料中。
- 无块时旧Overview≤4096 UTF-8字节必须全文原样保留，状态为 `continuity_status=legacy_unverified`；超限非零退出，stdout为空，绝不整段延后。两种状态均只证明结构提取，不证明语义覆盖；块重复、错位、未闭合或损坏拒绝，不能跨章节，围栏代码示例不算真实标记。空块或仅空白块拒绝；非空但字段不完整仍为explicit_unverified，必须报告语义缺口，不当作完整覆盖。
- 旧Overview的保留边界止于围栏外下一个一级/二级标题（`#` / `##`），不是整个主文件；Overview内部子标题使用 `###` 或更深级别。同级 `## Goals` 不属于Overview，不能假定已召回；legacy_unverified仍须报告目标等缺口。仅获授权write/tidy可整理标题归属，recall不自动折叠/迁移标题。
- `overview_outside_continuity_bytes=N` 统计Overview中块外的字节（含章节标题/背景，不含标记），不证明背景含义或覆盖程度。N>0时简要说明“块外可选背景未加载”，不把该计数当语义缺口已解决的证明。
- 当前接手状态取 `hx:recent`（阶段目标与阶段验收、停点与工作定位、未完成改动、验证命令/日期/范围、当前阻塞/依赖/风险与未知）；**当前TODO唯一事实源为 `hx:pending`**。hx:pending完整保留所有行，包括已勾选项目、空行、缩进、懒续行和代码；只有明确的 `hx:done` 默认不读。不根据checkbox或关键词猜语义、完成状态或授权，不能假设遗留说明也已完成。主文件其他位置（含其他章节）出现未完成或疑似任务时拒绝并提示整理，不静默遗漏。Current State锚点外说明有界保留，不当作新任务。
- `pending_completed_items_omitted=0` 仅为兼容元数据，表示未按勾选状态省略pending内容；不展示，不证明语义完整。已勾选项目只作上下文，放在末尾接手区前或其原关联上下文中，不列为开放TODO、不改checkbox、不改变父子归属；其持续约束、门控、风险与未决决定仍须保留。完整pending计入原预算，超限须先显式整理，不能删行或增加预算。
- 仅从主日志目录 `Handoffx_Logs/` 按编号取最近N条，返回实际数量；默认不遍历年归档 `Handoffx_Logs.archive/<年>/`，不足N条不从归档补齐。缺失历史仅在用户显式请求详情时按已知确切路径查询；不知道编号时先读 `Handoffx_Logs/INDEX.md`（日志总目录，含年归档）定位，再读那一条，不整目录通读。有合法 `<!-- hx:recall -->` … `<!-- /hx:recall -->` 块时只读该摘要；无摘要且全文≤2048字节才读全文，旧长日志仅返回编号、时间、有界标题及路径，标明降级。摘要重复、未闭合等损坏必须报错；日志代码围栏未闭合且出现hx:recall字样时也必须报错，不能降级冒充成功。无hx:recall字样的旧日志若围栏未闭合，只返回元数据并标明 `legacy_unclosed_fence_metadata_only` 警告，不能声称读到正文或摘要。
- 默认不展开GOTCHAS正文、Architecture、Conventions、Build、Decision、其他可选背景或递归引用。当前有效关键约束及决策原因/出处应在continuity，当前阻塞与未知应在recent，不能仅在默认不读的资料中；未读资料不声称已读，也不从标题推测停点、下一步或验证结论。
- 各局部上限不是可以同时满额的额度；默认6条也受总量约束，不自动减条或丢当前信息。
- **其他电脑**：项目里有其他电脑的备份（`.agent-sessions-sync-hx/machines/<机器>/`，交接收尾自动导出）时，运行时在日志之后追加只读的 `cross-machine backups` 段：每台一行（最近会话结束时间、会话数、记忆数），并带入本机没有或内容不同的记忆正文。该段在日志之后才分配，≤4096字节；放不下的记忆只列名字，再不够写 `cross_machine=deferred_budget`。不读本机自己的子目录；读到的记忆只用于本次会话，**不写入本机 `~/.claude`**，与本机记忆冲突时以项目交接文件为准并提示用户。没有该段时不提。
- 预算失败时说明需单独整理当前清单或由用户显式指定资料读取；**禁止全文补读、分批拼回全文或更换工具绕预算**，不自动缩短TODO、不自动重试全文、不写摘要、不迁移历史。显式详情请求才按已知确切路径定向读取，并与默认召回范围区分；不是失败兜底，不提供不受限`--full`。
- 日志或 Decision 编号重复（常见于多台电脑同步后）时运行时拒绝：报告重号文件，建议运行 `/handoffx-tidy` 修复后重试，不自行改号。
- 脚本被拒绝、不可运行或文件/锚点出错时停止并如实报告，不通过其他工具或子代理绕过；不能声称采集成功。旧/混合布局仅按 `references/layout-gate.md` 请求确认，未授权不升级、不手读旧主文件全文替代。缺主文件则提示初始化，不代做。

## 交接时间与时效

报告开头必须给出上次交接记录时间、距今多久及来源日志编号：
- 使用运行时的 `last_handoff_log`、`last_handoff_at`、`recall_now` 和 `elapsed_days/hours/minutes`。时间带明确日期与时区（`Z` 为 UTC）；天数按完整24小时计算，可写“距今4天3小时”，不足一天写小时/分钟，不足一分钟写“不到1分钟”。不要仅写“今天/昨天”，不要把不足一天显示成“已过1天”。
- 时间取主日志目录中最新编号日志 frontmatter 的 epoch，不取文件修改时间、召回时间或文件名。仅有记录时间不证明 postflight 已完成，默认称“上次交接记录时间”；若有明确的成功完成证据，另行说明，不编造完成时刻。
- `date_only/unknown`：保留 `last_handoff_recorded` 原文（若有），说明缺少可信epoch/时区，距今时长无法准确计算，不猜测。`invalid_epoch/clock_unavailable/future`：正常提醒时间元数据异常、系统时间不可用或记录时间晚于当前时间，不报虚构/负数天数。
- `no_logs`：显示“主日志目录暂无交接日志，上次交接时间及间隔未知”，仍汇报已有状态和待办；不据此断言归档也无记录。
- 旧日志中的“今日/明日”关联到该日志的日期，不能当作召回当日任务；日期不确定则标注待确认。旧验证结果注明记录日期，不当作当前健康检查。

## 验证来源与时间

`verification_status=structured_claims_unverified`仅说明验证声明格式合法；`legacy_unverified`表示没有结构化声明，都不认证真实测试。将声明转成简明人话：来源＋命令/结果（保留对象、数量与统计口径）＋实际执行时间或“未提供”＋未验证范围。`runner_report`必须说“测试驱动报告，本次未重跑”，不能说本次Agent实测。

`performed_at: unknown`必须明确“实际测试/事件执行时间未提供”。交接frontmatter date/epoch、`last_handoff_at`及recall_now都不能补执行时间；也不能把记录当日缩略为“当日执行”。历史散文与声明冲突时标明冲突，不选择较新时间消除未知。

## 语义覆盖与冲突检查

工作定位包括已知项目/工作副本位置；区分本次召回目录和已记录的代码工作副本，前者不证明后者身份；保留已记录的未提交/未保存改动，未记录不代表工作区干净，不为补齐字段运行git。关键技术约束包括已记录的接口与数据不变量。

`explicit_unverified` 与 `legacy_unverified` 均不是完整性认证。结构合法不代表语义齐全，必须逐项检查总目标/受益者与问题、阶段目标、成功标准/阶段验收、范围/非目标、关键约束/授权门控、有效决策及原因/出处、停点/工作定位/未完成改动、验证命令/日期/范围、阻塞/依赖/风险/未知、下一步与完整TODO。最终报告逐项列出缺失、冲突或仅有占位的覆盖缺口；没有证据时写“未记录/待确认”，未知不等于没有。

**决策必须实际说出三项**：“选择了什么；为什么（当前仍有效原因）；出处”。原因已在continuity就直接复述，不得用“原因见原文/依据简述”、只给链接或给“原因已覆盖”打勾代替。未记录原因才明确说未记录。目标/成功标准/边界/门控同样以可读内容验收，不以字段名或勾号验收。

按时间、对象、统计口径复述，不重分配数量：历史“未实现”与后来“已完成”是先后关系；某功能“新增3项测试”与回归“总计6项通过”分别保留，不能合成“该功能6项测试通过”。已有增量/总量说明不新增疑问或待办。若recent已把总量归给单功能，列明recent与验证声明/日志摘要各自口径及归属缺口，不照抄为阶段验收事实，也不静默改写来源；仅范围归属不明则标未记录，不猜子集通过数。

不能从项目标题或TODO反推目标，不能因时间较新就静默覆盖冲突（例如Overview版本与recent版本不一致）；列明各自来源及冲突，旧验证不当作当前健康证明。方向要求缺失/冲突时，改变目标或不可逆操作前先询问确认，但不因此阻断每项无害任务；本次recall仍只读。维护仅在write/init或获授权整理中进行，不在recall猜测、补写或生成第二份状态快照。

## 最终结果

报告只用以下三个区块与末尾接手区；采集元数据转成必要的人话，不逐项罗列key=value：
1. **交接时间与读取范围**：绝对时间、时区、间隔、日志编号；实际条数、摘要/短全文/元数据降级及未读缺口。
2. **项目方向与覆盖缺口**：总目标/受益者与问题、成功标准、范围/非目标、关键约束/授权门控、有效决策及原因/出处；逐项列出未记录、冲突与待确认，说明continuity状态只代表结构提取。
3. **当前状态与近期交接**：阶段目标/阶段验收、工作定位/未完成改动、验证命令/日期/范围、阻塞/依赖/风险与未知；日志仅呈现已读事实，旧验证标日期，不当作本次实测。有跨机段时在此加「其他电脑」小节：哪台、最近一次在本项目工作的时间，以及带入的记忆要点。当前关键约束、风险、来源说明与覆盖缺口均放在末尾接手区之前，不展开可选背景。

回复最后固定以下接手区（顺序：上次停在哪里 → 当前TODO → 下一步，下一步在最末），**之后不追加总结、来源、风险或结束语**；计数与完整性说明也只放前文：
