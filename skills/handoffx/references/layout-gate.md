# 旧布局安全门（共享规则）

仅检测到旧布局时执行；正常布局不打印说明。不重复向用户复述流程。默认提示遵守200字上限，不能隐去冲突、失败或必要确认。

**旧布局检测 → 询问 → 标准升级**（按内容判定，不按文件名猜）：
1. 根下存在任一旧版件（旧版 `HANDOFF.md` / `Handoff_Logs/` / `Handoff_Decisions/`）→ 先 `bash <skill-path>/scripts/handoffx-upgrade.sh --dry-run --root <项目根>`，内部核对判定与清单；对用户只简述影响，完整清单按需展开。
2. 问：「检测到旧版 handoff 文档布局，是否现在升级到 handoffx 布局？（原子迁移、失败自动回滚；v1 单文件另留 .pre-v2-backup，v3 原地改名：git 仓库靠 git 回退，非 git 项目自动先打 .handoffx-pre-upgrade-<时间>.tar.gz）」
3. 确认 → `--apply`，回显结果、残留清单与后续动作；未确认 → 不写任何文件。exit 1 = 迁移已完成但后置检查未过：不重试、不回滚，用 `/handoffx-tidy` 补章节再继续；exit 3 = 迁移器拒绝、未迁移，按输出处理后重跑。
4. 新旧并存 / 无法判定 → 脚本拒绝并点名，转述给用户，不猜。
5. 用户本轮已明确要求升级 → 直接 --dry-run 再 --apply，不再重复询问（影响仍需简述；脚本拒绝或要求 --sync-paused 时仍停下转述）。

升级询问只需：「发现旧版布局，是否升级？将保留回退方式；确认前不改文件。」完整备份策略与残留清单按需展开，不自动继续处理被拒绝的迁移。
